用 GitHub Actions 构建两个自动信息雷达

记录 PubMed 公共卫生文献和 AI 工作流资讯的自动发现、归档与 Pages 部署方式。

为什么做信息雷达

我借助 Cursor 和 GitHub Actions 搭建了两个自动更新页面：

  • PubMed 公共卫生文献雷达：发现与研究设计、生物统计、流行病学和真实世界证据相关的文献；
  • AI 工作流资讯雷达：关注 AI 编程、数据自动化和研究工具。

它们的定位是“候选选题入口”，用于减少日常浏览成本，不代表本站推荐，也不能替代系统综述、正式检索或证据质量评价。

仓库与部署结构

如果源码不适合公开，可以使用两个仓库：

  1. 私有源码仓库：保存抓取脚本、配置、数据处理逻辑和 GitHub Actions 工作流；
  2. 公开 Pages 仓库：只保存构建后的静态 HTML、CSS、JavaScript 和必要的公开数据。

私有仓库的工作流按计划运行：抓取公开信息、生成候选内容、构建静态页面，验证通过后再将产物推送到公开 Pages 仓库。

凭据与权限

跨仓库部署需要写入凭据时，优先使用 fine-grained personal access token，并遵循最小权限原则：

  • 只授权目标 Pages 仓库；
  • 只授予部署所需的 Contents 读写权限；
  • 将 Token 保存为私有仓库的 GitHub Actions Secret；
  • 不把 Token 写进源码、配置文件、日志、截图或文章；
  • 定期检查有效期，不再使用时及时撤销。

如果部署可以使用 GitHub 原生的 GITHUB_TOKEN 或 GitHub App，应优先考虑它们，减少长期个人凭据的暴露面。

从聚合页到内容资产

单纯自动抓取容易形成“信息堆积”。后续工作流应增加人工编辑门槛：

  1. 判断信息是否与临床统计、研究方法或数据工作流相关；
  2. 写清楚为什么值得阅读；
  3. 提出可以转化为博客文章或公开案例的角度；
  4. 只有经过人工评估的候选内容才进入写作清单。

目前两个页面仍在逐步升级：

  • PubMed 公共卫生文献雷达
  • AI 工作流资讯雷达
